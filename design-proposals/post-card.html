Feed post card — proposal v2 (Hero + compact, vibe theming)

Two lyric layouts in one component: Lyric Hero when the post is ≤2 lines or under ~80 characters; compact at 17px with a 4-line clamp and “more” for long or multi-moment threads. Header, player row, song row, and actions share the same structure in both modes.

Vibe palette (sources in repo)

  • lib/discover-vibes.ts — DISCOVER_VIBE_COLORS (HYPE, PROUD, LOVE, CHILL, HOPE)
  • components/post-card.tsx — EMOTION_COLORS (heartbreak → PAIN in this mock)
  • components/mini-player.tsx — VIBE_COLORS (broader emotion set; chill/hope/love align)
  • Unknown / missing vibe → gold default #E8C547 (same as Discover fallback via discoverVibeColor)

Per vibe: --vibe-fill (accent), --vibe-text (lighter label accent), --vibe-glow (soft top-corner gradient). Applied to card background gradient, mood chip, play control, progress bar, and active action tint.

Lyric body stays --text (not vibe-colored) so long passages always meet AA. Vibe fill on white lyric text fails AA for some hues — do not use fill as lyric color.

Performance rules (feed card implementation)

  • CSS linear-gradient only for card tint — no backdrop-filter, no blur, no extra composited layers.
  • No animated layers on the mounted feed card (skeleton → content crossfade should be instant swap).
  • No additional font families beyond Geist Sans + Lora already loaded app-wide.
  • No network or image processing at render time; artwork URL is a static <img> or CSS placeholder.
  • Fixed min-height on hero and compact lyric zones so skeleton and final card share the same box (no CLS).

Estimated cost per card (mobile feed): ~1 card paint (~2 gradient fills), ~45–55 DOM nodes, 4×44px hit targets, 1 optional progress bar repaint on tick; ~0 KB extra fonts; 0 extra HTTP if artwork cached. Budget ≈ 0.3–0.6 ms style/layout + 0.2–0.4 ms paint on mid-tier GPU at 390px width (excluding audio decode).

Future: artwork-derived accent (not in this mock)
On upload, sample dominant/median RGB from artwork once (canvas or server worker), derive accent, accentText, and glow with the same WCAG guardrails, store on songs.artwork_accent (or post snapshot). Feed reads stored tokens only — no per-scroll color extraction.
